## ADR-0001: اعتماد branch `stabilization/baseline-and-security` كفرع العمل التأسيسي
- **التاريخ:** 2026-08-24
- **السياق:** الفرع `main` يحمل baseline غير محمي؛ الخطة المرجعية §1.1 تأمر بفرع تثبيت قبل أي ميزة.
- **الخيارات:** (أ) العمل مباشرة على main — مرفوض: يفقد قابلية العزل والمراجعة. (ب) فرع تثبيت — مُعتمد.
- **القرار:** كل مهام GF-0001..GF-000x (تثبيت وأمان) على هذا الفرع، والدمج إلى main عند عبور بوابة G1.
- **النتائج:** حماية main من كسور وسيطة؛ يتطلب انضباط rebase.
- **الاسترجاع:** حذف الفرع (لا أثر على main).
- **الاعتماد:** مالك المنتج (عبر الخطة المرجعية).

## ADR-0002: تجميد تعديلات schema حتى GF-0006 (سياسة change-freeze للمخطط)
- **التاريخ:** 2026-08-24
- **السياق:** الفحص كشف فجوات مخطط جوهرية (Warehouse، ledger، BOM versions) لكن تعديلها الآن يسبق حماية المسارات ويوسع نطاق المرحلة 0.
- **الخيارات:** (أ) إصلاح المخطط فورًا — مرفوض: يخل بتسلسل المراحل وقاعدة أصغر تغيير آمن. (ب) تجميد موثق — مُعتمد.
- **القرار:** لا تعديل على `schema.prisma` قبل إغلاق P0 الأمنية وعبور G1. الفجوات موثقة في `DATA_AND_MIGRATIONS.md §3`.
- **النتائج:** عمل أمني نظيف التتبع؛ الفجوات مؤجلة بترتيب معلوم.
- **الاسترجاع:** قرار تنظيمي فقط.
- **الاعتماد:** قاعدة 0.2/0.3 من الخطة المرجعية.

## ADR-0003 (مسودة): مصير الأحداث المالية المعلنة في README
- **التاريخ:** 2026-08-24 — **حالة: مُقترح، غير معتمد بعد**
- **السياق:** README يعد بسحب مخزون وقيود آلية عبر أحداث، والكود يحتوي `emit` في موضعين **بلا أي listener**. EventEmitter2 in-process لا يضمن ذرية مع قاعدة البيانات.
- **الخيارات:** (أ) outbox pattern (جدول أحداث + معالج) — أثقل لكن موثوق وقابل للتدقيق. (ب) تنفيذ الآثار داخل نفس `prisma.$transaction` وإسقاط ادعاء الأحداث — أبسط وأكثر أمانًا محاسبيًا. (ج) إبقاء events in-process للتنبيهات غير المالية فقط (low stock notifications).
- **القرار المقترح:** (ب) للآثار المالية + (ج) للتنبيهات التشغيلية، وإعادة كتابة README ليعكس الحقيقة. يُحسم نهائيًا في المرحلة 2/7.
- **الاسترجاع:** لا ينفذ شيء قبل الاعتماد.

## ADR-0004 (مسودة): توحيد منفذ الخدمة على 3005
- **التاريخ:** 2026-08-24 — **حالة: مُقترح**
- **السياق:** backend افتراضي 3000 (`main.ts:39`)، Flutter يطلب 3005 (`api_client.dart:14-16`)، commit سابق ادعى التحويل إلى 3005. التشغيل الحالي يفشل اتصالًا دون تدخل يدوي.

- **الاسترجاع:** متغير بيئة فقط.

## ADR-0005: تقييد النشر الشبكي وpgAdmin اختياري في docker-compose
- **التاريخ:** 2026-08-25 (GF-0006)
- **السياق:** P1-06 — الخدمات كانت منشورة على كل الواجهات (`0.0.0.0`) بكلمات مرور ثابتة، وpgAdmin يعمل دائمًا ببيانات ضعيفة.
- **الخيارات:** (أ) إبقاء النشر الشامل للراحة التطويرية — مرفوض: بيئة التطوير على شبكات غير موثوقة أمر شائع. (ب) ربط localhost فقط + pgAdmin تحت profile اختياري — مُعتمد.
- **القرار:** كل الـ ports تصبح `127.0.0.1:...`، وpgAdmin تحت `--profile tools` لا يعمل افتراضيًا، وكل البيانات من `.env` بصيغة `${VAR:?msg}` (فشل تشغيل عند النقص).
- **النتائج:** الوصول من أجهزة أخرى (مثل الهاتف الفعلي للمحاكاة) يتطلب SSH tunnel أو تعديلًا واعيًا — مقبول للأمان. للتطوير الميداني لاحقًا يُضاف binding مؤقت موثق.
- **الاسترجاع:** revert الملف — لا أثر على الكود.
- **الاعتماد:** قاعدة 0.5 من الخطة المرجعية (الأمن أولًا).

## ADR-0006: كلمة مرور admin الأولية من البيئة (SEED_ADMIN_PASSWORD)
- **التاريخ:** 2026-08-25 (GF-0006)
- **السياق:** P1-02 — كلمة المرور كانت منشورة في README وseed.
- **الخيارات:** (أ) توليد عشوائي وطبعها مرة في السجل — لا يصلح لبيئات CI ويشجع النسخ. (ب) قيمة افتراضية جديدة ثابتة — نفس المشكلة. (ج) من البيئة مع فشل واضح — مُعتمد.
- **القرار:** seed يقرأ `SEED_ADMIN_PASSWORD` ويفشل فورًا بدونها؛ مثال موثق في `backend/.env.example` بلا قيمة حقيقية؛ README يشرح الآلية بلا نشر أي سر.
- **النتائج:** خطوة إعداد إضافية واحدة للتطوير مقابل صفر أسرار في المستودع.
- **الاسترجاع:** revert seed.ts.
- **الاعتماد:** قاعدة الأمن (لا أسرار في Git).
