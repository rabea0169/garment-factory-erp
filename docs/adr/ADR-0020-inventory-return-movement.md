# ADR-0020: حركة إرجاع المخزون (RETURN) — الدلالة والنطاق المالي

## Context

كان نوع حركة `RETURN` في `StockMovementType` محجوزًا بلا مسار استخدام (التعليق القديم: «يُفعّل مع مرتجعات المشتريات في GF-0009»)، بينما الحاجة التشغيلية الفعلية اليوم هي **مرتجعات الإنتاج**: خامات صُرفت لأمر تشغيل عبر `consumeMaterial` ثم أعادها خط الإنتاج إلى المخزن (بقايا قص، توفير نصف الخامة، إيقاف أمر). لم يكن لهذه الحالة تمثيل صريح — كانت تُسجّل كـ RECEIVE اصطنائي (يؤثر على متوسط التكلفة المرجح بلا شحنة فعلية) أو ADJUSTMENT (يخفي المرتجع في تسوية جرد).

## Decision

**تمثيل صريح بحركة RETURN** عبر `POST /inventory/return` (ReturnStockDto: rawMaterialId + quantity + reason إلزامي + reference اختياري لأمر التشغيل المصدر؛ warehouseId اختياري — غيابه يوجّه الإرجاع لمخزن الخامات الافتراضي الحتمي وفق INV-6: أول مخزن خامات نشط بترتيب createdAt، وتحديده صراحةً يبقى متاحًا لمخزن الإرجاع الفعلي):

1. **المخزون والدفتر**: يزيد رصيد الخامة والمستودع كالاستلام (delta موجب)، ويقيّد سطر `StockLedgerEntry` واحد بنوع `RETURN` مع سبب الإرجاع في notes — نفس قواعد ADR-0007 (لا رصيد سالب) ونقطة التسلسل الذرية (increment واحد).
2. **بلا قيد GL**: المرتجع داخلي بلا طرف خارجي — الاستهلاك الأصلي هو الذي قيّد WIP (من `consumeMaterial`)، وإرجاع الخامة يعكس جزءًا من ذلك الاستهلاك ماديًا لا محاسبيًا (الخامة تعود للمخزون والتكلفة تبقى في WIP حتى إعادة صرفها أو إقفال الأمر). أي قيد هنا (مثل Cr WIP / Dr INVENTORY) كان سيمس قيد الاستهلاك المتزامن أو يزدوج محاسبيًا مع إعادة الصرف اللاحقة — لذلك لا قيد، والقيمة في الدفتر (totalValue = الكمية × تكلفة الخامة الحالية) للتدقيق التشغيلي لا للترحيل.
3. **بلا متوسط مرجح**: لا يُعاد احتساب `costPerUnit` (سلوك الصرف لا الاستلام) — المرتجع لا «شحنة شراء» فلا يُدخل تكلفة جديدة إلى المتوسط؛ يعود بكمية فقط ويُقيَّم للعرض بتكلفة الخامة الجارية. الوسم البديل المرفوض: إدخاله بمتوسط مرجح كان يخفض/يرفع تكلفة الوحدة بلا معاملة شراء فعلية.
4. **idempotency**: النطاق `inventory.return` (المفتاح موجود سابقًا في IDEMPOTENCY_SCOPES ومفعّل الآن) — نفس ضمانات receive/issue.
5. **الأدوار**: `INVENTORY_MANAGER` فقط (+SUPER_ADMIN يتجاوز) — مثل باقي حركات الكتابة.

مسار هدر البضاعة الجاهزة (`POST /inventory/movements/waste-finished-good`) يُقرر في هذا ADR كمرافق: هدر التام **يرحّل** قيدًا (Dr WASTE_EXPENSE / Cr FINISHED_GOOD_STOCK) بخلاف المرتجع، لأن الهدر خسارة فعلية تُخرج القيمة من الأصول، بينما المرتجع مجرد إعادة تصنيف مادي داخل الدورة.

## Consequences

- `InventoryService.return(input, userId?, tx?, eventsCollector?)` يدعم externalTx (نمط INV-1: الأحداث تُجمع للمستدعي الأعلى) — متاح لـ production-workflow مستقبلًا لإرجاع آلي عند إلغاء أمر.
- أحداث `STOCK_ADDED` تُبث للحركة (RETURN inbound في buildStockEvents) — لا STOCK_LOW جديد لأن الرصيد يرتفع فقط... يبقى فحص العتبة كما هو (غير مؤذٍ).
- سجل التدقيق (INV-7): `STOCK_RETURNED` بالرصيد قبل/بعد داخل نفس المعاملة عند توفر الفاعل.
- **محدودية موثقة**: مرتجعات المبيعات (من العميل) ومرتجعات المشتريات (إلى المورد) خارج هذا القرار — لهما طرف خارجي وأثر مالي (خصم عميل/دائن مورد) وتحتاج قيودًا خاصة عند بناء مساراتها؛ هذا ADR يخص مرتجع الإنتاج الداخلي فقط.

## Migration/Rollback

لا تغيير مخطط: `RETURN` قيمة enum موجودة في `StockMovementType` منذ GF-0007 وعمود `type` في `stock_ledger_entries` يقبلها. Rollback = تعطيل مسار الـ API (لا بيانات قديمة تعتمد عليه).
