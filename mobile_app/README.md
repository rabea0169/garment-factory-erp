# Garment Factory ERP — Flutter Mobile App

تطبيق Flutter الميداني لنظام Garment Factory ERP. يعتمد التطبيق على JWT صادر من Backend، ويخزن التوكن في **Keychain/Keystore** عبر `flutter_secure_storage`، ولا يستخدم `SharedPreferences` لتخزين بيانات الجلسة.

## التشغيل المحلي

بعد تثبيت Flutter SDK، شغّل الأوامر التالية من مجلد `mobile_app`:

```bash
flutter pub get
flutter analyze
flutter test
flutter run
```

عنوان الخادم الافتراضي (MOB-5) هو الإنتاج عبر HTTPS:
`https://garment-factory-erp-production.up.railway.app` — لا HTTP مكشوف في أي افتراضي.

للتطوير المحلي فقط، تجاوز العنوان وقت البناء/التشغيل عبر `--dart-define` (بدون تعديل الكود):

```bash
# Android Emulator (10.0.2.2 = مضيف جهازك من داخل المحاكي)
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3005

# iOS / macOS / Web / سطح المكتب
flutter run --dart-define=API_BASE_URL=http://localhost:3005

# جهاز فيزيائي على نفس الشبكة
flutter run --dart-define=API_BASE_URL=http://192.168.1.10:3005
```

ملاحظة: HTTP غير المشفر لا يعمل على Android إلا للعناوين التي تمررها صراحة
بهذه الطريقة وقت التطوير؛ عنوان الإنتاج الافتراضي HTTPS دائمًا، و`AndroidManifest`
لا يحتوي أي علامة `usesCleartextTraffic`.

## المصادقة وانتهاء الجلسة

يضيف `ApiClient` التوكن تلقائيًا إلى كل طلب محمي (MOB-1). عند استلام HTTP 401 من
مسار غير مسارات المصادقة نفسها، يجرّب `AuthRefreshInterceptor` تجديد الجلسة عبر
`POST /auth/refresh` بآخر `refresh_token` محفوظ (تحديث واحد فقط مهما تعددت
الطلبات المتزامنة)، ثم يعيد الطلب الأصلي مرة واحدة؛ إن فشل التجديد (رمز تحديث
ملغى/منتهٍ) تُمسح الجلسة المشفرة بالكامل ويُعاد المستخدم إلى شاشة تسجيل الدخول.
عند الخروج (MOB-2) يُبلَّغ الخادم `POST /auth/logout` بأفضل جهد قبل مسح التخزين
المحلي. كما يمنع الراوتر فتح الشاشات المحمية دون توكن محفوظ.

بيانات التقارير لا تستخدم fallback وهميًا. إذا كان endpoint `/dashboard/stats` غير متوفر أو أعاد payload غير مكتمل، يعرض التطبيق رسالة خطأ وزر إعادة محاولة بدل عرض أرقام قد تبدو حقيقية.

## القدرة اللا-اتصالية (MOB-3)

التطبيق يعمل بلا اتصال عبر مسارين فوق `Hive` (المصرّح به في pubspec):

### 1) ذاكرة قراءة (CacheService)

`core/services/cache_service.dart` يخزن **آخر حالة ناجحة** لثلاث شاشات:

| الشاشة | المفتاح | السلوك عند فقد الاتصال |
| --- | --- | --- |
| قائمة العمال (`/hr/workers`) | `hr_workers` | عرض الكاش مع شارة «بيانات مخزنة» ووقت آخر تحديث |
| أوامر التشغيل (شاشة الإنتاج) | `production_work_orders` | نفس الشارة مع استمرار العرض |
| لوحة التحكم (`/dashboard/stats`) | `dashboard_stats` | نفس الشارة |

- بعد كل **نجاح شبكة** تُحدَّث القيمة فورًا (`writeThrough`).
- عند **انقطاع الشبكة** (تصنيف `ApiClient.isNetworkError`) تُعرض آخر حالة ناجحة
  مع شارة `AppCachedDataBanner` (بيانات مخزنة + لحظة التخزين)؛ إن لم يوجد كاش
  تظهر شاشة «لا يوجد اتصال» المخصصة (`AppOfflineView`).
- عمر الكاش الافتراضي 24 ساعة (`read(key, maxAge)`) — الإدخال المنتهي يُحذف.
- فشل تهيئة Hive يعطّل الكاش بصمت: التطبيق يعمل متصلًا كالمعتاد.

### 2) طابور كتابة صادر (OutboxService)

`core/services/outbox_service.dart` — عمليات **POST الإنتاج اليومي** (`/hr/production`)
و**الحضور** (`/hr/attendance`) عند فقد الاتصال:

- تُدرج في طابور Hive `{id, method, path, body, idempotencyKey, createdAt}` ويعيد
  التطبيق تأكيدًا عربيًا: «لا يوجد اتصال — تم حفظ التسجيل محليًا وسيُرسل تلقائيًا
  عند عودة الاتصال».
- عند عودة الاتصال (`ConnectivityService`) تُرسل العمليات **FIFO عبر ApiClient
  بنفس `Idempotency-Key`** الذي صدر وقت الإنشاء — إعادة الإرسال (replay) آمنة
  خادميًا: نفس المفتاح = نفس النتيجة المخزنة، فلا تكرار بيانات إنتاج/حضور.
- فشل الإرسال المستمر يُبقي العنصر في الطابور (يُعاد لاحقًا)؛ النجاح يحذفه.
- شاشات الإنتاج والعمال تعرض **شارة عدد المعلّقات** (`OutboxPendingBadge`) تتحدث
  لحظة الإدراج ولحظة نجاح الإرسال المتأخر.

**دورة شاشة الإنتاج أوفلاين (التكامل):** فتح الشاشة بلا اتصال → قراءة أوامر التشغيل
من الكاش بشارة «بيانات مخزنة» → تسجيل الإنتاج اليومي من شاشة العمال يذهب للطابور
→ شارة عدد المعلّقة تظهر أعلى الشاشتين → عودة الاتصال ترسل كل المعلّق تلقائيًا بنفس
مفاتيحه.

## قراءة بطاقات NFC لتحديد العامل (MOB-4)

شاشة الموارد البشرية فيها زر NFC بجانب البحث (حزمة `nfc_manager`): الضغط يبدأ جلسة
قراءة واحدة تتوقف عند أول بطاقة؛ إن كان العامل مرتبطًا بالبطاقة (`nfcId` أو الكود)
يُعبّأ البحث باسمه، وإلا يُعبّأ بمعرّف البطاقة نفسه. فشل المنصة (جهاز بلا NFC، NFC
معطّل، منصة غير مدعومة) يظهر رسالة عربية واضحة — لا crash.

## شاشات الموارد البشرية (MOB-8)

- **كشوف الرواتب** (`/hr/payrolls`): قائمة الكشوف مع مرشح حالة (الكل/مسودة/معتمد/
  مدفوع) وتحديث بالسحب وحالات فراغ/خطأ/تحميل — تفتح من أيقونة الدفعات في شاشة
  الموارد البشرية (أدوارها في الخادم: HR_MANAGER / GENERAL_MANAGER).
- **نشاط العامل**: من بطاقة العامل — تبويبا «آخر السلف» (`/hr/advances?workerId=`)
  و«آخر الإنتاج» (`/hr/production?workerId=`) بأبسط تمثيل.

## اللغة (MOB-6)

العربية (ar_EG) هي اللغة الوحيدة المدعومة: كل النصوص عربية مباشرة بلا طبقة ترجمة،
و`supportedLocales` تعلن `ar_EG` فقط كي يبقى اتجاه الواجهة RTL سليمًا. إضافة لغة
لاحقة تتطلب ملفات ARB + `flutter gen-l10n` (موثق بتعليق في `app.dart`).
